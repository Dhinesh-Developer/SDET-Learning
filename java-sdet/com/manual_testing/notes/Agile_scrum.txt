Scrum: -----------> it is a framework
------
    scrum is a framework through which we build software product by following agile principles.
- Scrum includes grouop of people called as scrum team. Noramally contains 5-9 members.

- product owner
- Scrum master
- DEv team
- QA team

Product owner:
------------
    - Define the features of the product
    - Prioritize features according to market values
    - Adjust features and priority every iteration, as needed
    - Accept or reject work results

Scrum master:
-------------
    The main role is faciliating and driving the agile process

Developers and QA:
------------------
    Develop and test the software


Scrum terminalogy:
-----------------
1. User Story: A Feature/module in a software
2. Epic: Collection of user stories
3. Product backlog: Contains list of user stories. Prepared by product owner.
4. Sprint/Iteration: period of time to complete the user stories. decided by the product
        owner and team, usually 2-4 weeks of time.
5. Sprint planning meeting: Meating conducts with the team to define what can be
    delivered in the spring and duration.
6. Spring backlog: List of committed stories by Dev/QA for specific sprint
7. Scrum Meeting: Meeting conducted by scrum master everyday 15 mins. Called as scrum call/ standup meeting.
    - What did you do yesterday?
    - What will you do today?
    - Are there any impediments in your way?
8. Sprint retrospective meeting: conducts meeting after completion of sprint. The entire team
    including both the scrumMaster and the product owner should participate
9. Story point: Rough estimation of user stories, will be given by DEV and QA in the form of fibonacci series.
    0 1 1 2 3 5 8.....
    1 story point = 1 hour/ 1 day (6 hours)
    Login --> Dev- 5  QA-3 = 8 hours/ 1 day
10. Burndown chart: Shows how much work remaining in the sprint. Maintained by the scrum master daily.

Defintion of Ready (DoR):
-----------------------
- user story is clear
- user story is testable
- user story is feasible
- user story defined
- user story acceptance criteria defined
- user story dependencies identified
- user story sized by development team
- scrum test accepts user experince Artefacts
- performance criteria identified, where appropriate
- team has a good idea what it will mean to demo the user story


Defintion of Done (DoD):
-----------------------
- code produced (all 'to do' items in code completed)
- code commented, checked in and run againt current version in source control
- peer reveiwed (or product with pari programming) and meeting development standards builds withput errors
- unit testing written and passing
- deployed to system test envirnoment and passed system testers
- Passed UST (user acceptance testing) and signed off as meeting requirements
- Any build/deployment/configuration changest are implemented/docuemnted/communicated
- relevant documentation/diagrams produced and/ or updated
- remaining hours for task set to zero and task closed.
